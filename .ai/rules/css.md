# Css

## Leaflet's stylesheet loads after app.css
Components import 'leaflet/dist/leaflet.css', which lands after app.css, so an override of equal weight loses (the map credit stayed white in dark mode). Scope map overrides as `.map-tiles.leaflet-container …` (both classes are on the map element) to outrank Leaflet's own `.leaflet-container …` rules.

## Skins are token overrides under html[data-skin], plus textures painted on the utilities
The look of the app (App\Enums\ThemeStyle: classic, aegean, taverna) is stamped on <html> as data-skin beside data-mode (Blade for the first paint, applyTheme() in resources/js/theme.ts after). A skin is one block `html[data-skin='x'] { --color-…, --radius-…, --font-display… }` and a full `html[data-skin='x'][data-mode='dark']` block (define every token there, the classic dark block has the same specificity as the skin's light block). Components never branch on the skin. What tokens cannot carry is painted on the generated utilities themselves (`html[data-skin='aegean'] :is(.bg-surface, …) { background-image }`, inline SVG noise generated with feTurbulence). The owner asked to lose a Greek-key frieze along the navigation (2026-11-01): texture yes, ornament no. Taverna goes further and paints the page the other way round: cream writing on a terracotta wall, dark writing on light-ochre paper. The paper tokens live on the surface utilities themselves (`html[data-skin='taverna'] :is(.bg-surface, .bg-surface\/92, .bg-surface-2, .bg-surface-3, .bg-accent-soft, .bg-bubble-theirs, .bg-inset) { --color-ink: … }`), plus a `@layer base` rule giving those elements `color: var(--color-ink)` because colour inherits as a value; a new surface-like utility must be added to both lists or its text stays cream. `--color-inset` and `--color-on-ink` are tokens for that reason (see the js rule). A skin may paint the navigation: the rail, sidebar and phone top bar carry `skin-nav`, the phone tab bar `skin-tabbar` (AppLayout, PageHeader), and a skin re-sets the colour tokens inside them (`html[data-skin='taverna'] .skin-nav { --color-canvas: … }`), so the same utilities draw differently there; keep those two classes on those elements. Where the top bar is painted, the browser colour (ThemeStyle::browserColors, theme.ts) is the navigation's colour, and the Android bars' icon style follows isLightColor() of it, not the mode. The canvas colour of each skin and mode must match in three places: ThemeStyle::browserColors(), themeColors in theme.ts, and WebAppShellTest. Check a skin on /dev/kit by setting document.documentElement.dataset.skin in the console.
